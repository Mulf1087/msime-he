# 水杉 macOS 独立小鹤音形模式

## 已确认的目标

用户选择新增独立的“小鹤音形”模式，保留现有小鹤双拼。普通输入按本机鼠须管现用小鹤音形的固定编码和候选顺序处理，重点验收一简、二简和一至四码输入。此工作交付本机可用的 macOS 定制版本，不自动发布到 GitHub。

## 已核实的现状

水杉 0.55.0 已完整导入此前转换的 58,552 条快捷短语，但普通双拼候选与快捷短语分别排序、合并、去重。开启混输不能恢复固定码表首选。现有短语数据应保留，新增模式使用独立码表。

鼠须管已部署方案为 `flypy`，主表是 `build/flypy.table.bin`。它开启 `flypy_top`、`flypy_sys`、`flypy_user` 等表；`flypy_sys.txt` 有 8,452 条原始行，上一轮合并未包含。主表关闭组句、补全及用户学习；每页五项，分号选次选，方括号翻页，Tab 和右 Shift 取消组字。拼写器最长四码，开启自动选择，匹配式为 `^;.$|^\w{4}$`，空码策略是 `max_length`。这些配置仍需配合实际 Rime 按键会话确认具体提交时机。

用户提供的 2025 文本码表不能直接视为当前 Rime 主表的逐条副本。当前已部署表及当前启用的个人表是迁移依据，文本文件用于差异核对。

## 用户可见行为

1. 输入方案中新增“小鹤音形”；切换后直接输入编码。`sm` 首选“什么”，`b` 首选“不”，`bc` 首选“报”。
2. 一至四码按完整编码查表；按当前鼠须管的最终候选顺序展示并去重。拼音、英文、emoji 混输、云候选、AI 和调频不改动此模式的候选顺序。
3. 空格和数字选词、分号次选、方括号翻页、退格与取消遵循参考方案。新模式每页五项，不覆盖其他方案的分页偏好。
4. 有码、重码、空码、第五键、标点顶屏和连续输入的提交行为用鼠须管参考会话逐项确定，避免把“四码”误实现成无条件提交。
5. 输入时显示原始编码，选择词条消费整段编码，不把形码当成拼音拆开。
6. 设置页提供本地码表导入及条目数；无表、损坏或版本不支持时明确报错，不静默回退到拼音候选。

本次对齐静态字词表及正常打字规则。Rime 的 Lua 计算器、日期时间脚本、`ok` 拼字、反查和历史重复等扩展不复制进首版；水杉现有相应工具继续通过原入口使用。这一范围需在动产品代码前向用户明示。

## 码表迁移与私人数据

在独立目录复制已部署 Rime 数据，不修改本机 Rime。通过本机 librime 在复制环境导出静态表翻译器的最终完整候选列表；导出时仅关闭自动提交以便读完候选，关闭动态 Lua 与历史翻译器，不改变静态表相对优先级。枚举一至四位小写编码，另导出有效分号快符。与提供的文本码表核对缺词和次序差异。

产物为独立 SQLite 数据库，表 `entries(code TEXT, rank INTEGER, text TEXT)`，唯一键 `(code,text)`，索引 `(code,rank)`；`PRAGMA user_version=1`。`rank` 是参考会话导出的最终次序，不用人工大权重替代。数据库放在运行时 `user_data/xiaohe-yinxing.db`，不参与官方词库分代更新。

个人词条、导出数据库、源文件和逐项差异只放在源码仓库外的本机交付目录。源码、单测、提交仅使用合成词条和非私人验收词。导入先校验文件大小、版本、表结构、编码、文本长度与重复，再原子替换；导入失败保留旧表。

## 实现归属

- `crates/engine/src/xiaohe/`：独立拼写状态、只读码表查询、完整编码消费和参考规则。新增 `SchemeType::XiaoheYinxing = 10`，已有 ABI 序号不变。
- `crates/engine/src/ime/`、`session/`：接入方案和选择、取消、提交规则，禁止套用拼音学习及候选覆盖。
- `crates/input-runtime`：传递引擎判定的自动提交事实和正常分页选择；不复制音形算法。
- `crates/client-core`：新增持久化方案值及中文方案回切；既有默认方案不变。
- `crates/client-services`、`host-api`：本地码表校验、原子导入、状态查询和引擎选项。
- `packages/ui` 与 `platforms/macos`：方案选择、码表入口、实际输入模式标识与工具栏标题。其余平台不宣告已支持新方案。

## 验收与交付

先用合成数据覆盖完整输入链：一码与两码重码、z 正常码位、分号冲突、四码单候选与多候选、空码、第五键、数字、标点、取消、退格、切换方案、缺表与损坏表。自动提交规则必须先有参考会话证据再落地。

实际迁移后检查全部一简、二简编码及全部导出编码的候选次序，统计差异但不把私人词条写进仓库日志。`sm`、`b`、`bc` 必须在原生会话中是正确首选，并在真实编辑器里验证选词和连续输入。

运行相关 Rust 测试、格式化、clippy、UI 类型检查和构建、macOS 原生测试及仓库 quick 门禁；报告跳过的平台，不以交叉编译代替系统输入法验收。按项目打包流程构建包含设置应用、输入法、核心词库和 CLI 的完整包，验证同源产物。安装前备份原应用和用户状态，验证新包后再替换，保留恢复路径。

## 代价与边界

需要维护一个本地定制版本；后续官方更新可能替换新增模式。主表导出需验证当前 librime ABI，且不以网络找到的其他版本词库代替本机数据。首次完整构建可能下载工具链及依赖，磁盘需保留至少 50 GB。当前可用约 148 GB。
