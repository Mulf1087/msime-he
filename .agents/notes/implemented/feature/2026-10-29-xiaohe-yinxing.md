# Agent Note: macOS 独立小鹤音形方案

Status: implemented

## Problem

快捷短语的候选合并和去重不能表达固定码表的首选顺序、完整编码消费与提交规则。用户已选择新增独立小鹤音形模式。

## Decision

采用 ABI 序号 10 的独立音形方案，规则放在 Engine，macOS 声明可用能力。使用用户导入的独立码表，保持既有方案默认值；私人数据留在仓库外。完整设计见 [方案说明](../../../../docs/superpowers/specs/2026-10-29-xiaohe-yinxing-design.md)。

检索现有笔记后，[快捷短语首页槽位](../../implemented/feature/2026-10-25-quick-phrase-first-page-default.md)和[macOS 快捷短语候选](../../implemented/feature/2026-10-17-macos-quick-phrase-candidates.md)解释现有混输行为，与新方案独立保留。五笔自动提交偏好只描述五笔，不能直接作为音形规则；脚本插件的插入与重排能力不控制输入状态和自动提交，不能完整承载此方案。

## Alternatives considered

- 调整快捷短语权重与槽位：数据已经导入，改动较少；但同词去重和拼音状态仍会影响结果，无法对齐完整音形输入。
- 借用五笔方案与表：已有四码和顶字逻辑；但 z 码、补全、拼音反查与提交判定不同，混入个人数据也会污染五笔，故采用独立方案。
- 脚本插件：可在现有安装上导入；现有能力不能替换完整输入状态机，故不用。

## Validation

参考本机 librime 的复制会话确定一至四码、重码、空码、分号与连续输入规则。Engine、Runtime、Host API 的合成测试覆盖自动上屏、第五键顶字、翻页后的分号次选、插件旁路、导入回滚及缺表拒绝保存。完整个人表由仓库外的逐码验收脚本核对；真实安装验收单独记录，不以构建成功代替。私人数据不进入提交。跨平台的方案特性镜像同步 ABI 10，仅 macOS 能力列表提供新模式；Windows 读取共享版本表时跳过本宿主不认识的名称，防止负下标。

原生偏好加载也覆盖小鹤音形：旧原生设置窗口的控件刷新会在后台会话加载时执行，因此方案名称说明按稳定的 wire name 查询，并为未知方案兜底；不使用 `scheme - 3` 读取旧名称数组。`SchemeRoundTripPreferencesTest.mm` 直接测试无设置窗口时加载音形偏好、日文切换及回切，防止候选出现后因后台刷新控件越界而退出。

## Consequences

普通音形候选不经过拼音混输、脚本重排和动态调频；固定五项分页，不使用自动适应或多行展开。普通码表上屏跳过中英自动空格，保留码表字词原文。导入的 SQLite 文件独立于官方词库更新；缺表或坏表不能保存为活动方案。

需要构建并维护本地定制应用；参考码表导出必须匹配本机 Rime，不能以旧文本码表冒充已部署表。安装保留原应用和数据备份。
